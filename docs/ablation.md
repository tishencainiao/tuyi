# 消融实验设计（记忆消化 / 工具约束）

> 论文第 5 章「实验与分析」素材。目标：用可复现的小规模对比，说明「记忆消化」和「工具约束」各自的作用。

## 一、研究问题

1. **R1**：开启记忆消化后，生成的行程是否更贴合用户长期偏好？（个性化）
2. **R2**：工具约束（先查 POI / 天气 + `plan_trip` 结构化校验）是否降低了「编造景点 / 排错时间」？（幻觉）
3. **R3**：记忆消化带来的额外成本（LLM 调用次数 / 耗时）是否可接受？（工程权衡）

## 二、对比设计

| 组别 | 记忆消化 | 工具约束 | 说明 |
|---|---|---|---|
| A 对照组 | 关闭（`TUYI_DISABLE_MEMORY=1`） | 开启 | 只靠单轮对话与常识 |
| B 实验组 | 开启 | 开启 | 注入偏好标签 + 历史记忆 |
| （可选）C 组 | 开启 | 关闭工具校验 | 观察结构化校验的作用 |

操作：`node scripts/ablation.js`（会真实调用 DeepSeek，产生少量费用；A/B 各跑一轮）。

流程：
1. A 组：关闭记忆，直接跑测试场景；
2. 预热：开启记忆跑一次场景（产生记忆），等 Python 消化出 `insights`；
3. B 组：开启记忆再跑一次同一场景；
4. 对比两份输出与指标。

## 三、评价指标

| 指标 | 计算方式 | 说明 |
|---|---|---|
| 偏好命中率 | 输出中出现用户偏好词（如「慢节奏」「带父母」）的比例 | 人工或关键词匹配 |
| 行程完整率 | `plan_trip` 校验通过的项 / 总项 | 脚本自动算（ablation.js 输出） |
| 工具调用次数 | 事件序列里 `tool_start` 数量 | 脚本自动统计 |
| 响应耗时 | 从发起到 `done` 的秒数 | 脚本自动统计 |
| 重复/遗漏 | 是否重复询问已确认信息、是否漏掉硬性要求 | 人工评分 1–5 |

## 四、操作步骤（答辩前复用）

```bash
# 1. 确认 Key 已填
node check.js

# 2. 跑消融（约 3~5 分钟，花费约几分钱）
node scripts/ablation.js

# 3. 结果会打印两组回复与指标，手动整理进论文
```

建议换 3~5 个场景各跑一次（带父母 / 独自穷游 / 情侣 / 亲子 / 毕业旅行），汇总成表格。

## 五、注意事项（写论文时一定要写）

1. **样本量小**：这是课程级小规模实验，结论是「趋势性」而非统计显著；不要写成「证明了」。
2. **演示数据虚构**：`scripts/seed-demo.js` 生成的是虚构用户，论文中标注「演示数据」。
3. **模型随机性**：同一提示多次结果可能不同，结论要基于多次运行的平均趋势。
4. **成本**：单次对比约几分钱（DeepSeek flash），耗时 3~5 分钟。

## 六、预期结论（跑完再核对）

- B 组偏好命中率明显高于 A 组（记忆注入起作用）；
- 两组的行程完整率都较高（工具约束起主要作用）；
- B 组耗时略高（多一次记忆抽取 + 注入），但可接受。
