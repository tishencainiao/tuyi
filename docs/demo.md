# 答辩演示脚本（5~8 分钟）

> 现场演示用。断网也能跑（ECharts 已本地化）；DeepSeek / 高德需要网络。

## 一、准备

1. `E:\Learn\tuyi` 下确认 `.env` 已填 `DEEPSEEK_API_KEY` / `AMAP_KEY`；
2. `node check.js` 全绿（可选：`node test/smoke.js`）；
3. 可选：`node scripts/seed-demo.js` 让看板有演示数据；
4. 启动：`node server.js`，浏览器打开 `http://127.0.0.1:8787`；
5. 首次会跳转登录页：用测试账号登录（test1 / 123456），也可以现场注册一个新账号。

## 二、演示流程

### 第 1 步：聊天（约 2 分钟）
输入：「带爸妈去成都玩三天，预算中等，不想太累」。
看点：
- 流式输出（打字机效果）；
- 工具状态「正在查询景点 / 查询天气 / 整理行程」；
- 生成结构化行程卡片（时间 / 地点 / 活动 / 交通 / 花费）。

### 第 2 步：个人中心（约 1.5 分钟）
打开 `/profile.html`，看当前账号的画像与记忆。
看点：偏好画像（标签 + 一句话）、记忆条目（可现场「改 / 删 / 添加」）、行程记录——对应「记忆消化」产出与「记忆可编辑」。

### 第 3 步：偏好统计（约 1.5 分钟）
打开 `/dashboard.html`。
看点：
- 默认「我的旅行」页签：去过城市 / 旅行次数 / 总天数 / 平均预算 + 城市足迹表 + 城市与标签图；
- 切到「全局统计（含演示数据）」页签：KPI、标签分布、目的地 Top、预算档位、提问意图。
讲法：个人视角讲「用户自己的旅行画像」，全局视角讲「大数据元素——全体用户偏好统计」；演示数据为虚构，需在论文注明。
补充（约 1 分钟）：切到「我的旅行」里的旅行地图，省 / 市粒度切换，颜色深浅表示去过次数；现场点击一个城市演示手动标记「去过」（再点取消）。

### 第 4 步：记忆生效（约 1.5 分钟，可选）
再发一句：「你还记得我的偏好吗？推荐个适合我的目的地」。
看点：回复直接引用偏好（带父母 / 慢节奏 / 预算中等），并给出理由。

### 第 5 步：讲技术点（约 1 分钟）
- SSE 流式（降低等待焦虑）；
- Function Calling + ReAct（工具循环）；
- plan_trip 结构化校验 + POI/天气约束（防幻觉）；
- 记忆消化（抽取 → 消化 → 注入），Python 独立脚本；
- 看板统计（规则分类，可解释）。

## 三、故障预案

| 情况 | 处理 |
|---|---|
| DeepSeek 超时 | 重发一次；说明网络抖动 |
| 高德 Key 失效 | 工具返回 `ok:false`，系统会如实说「实时数据没查到」——正好演示降级逻辑 |
| 断网 | 看板图表仍可展示（ECharts 本地化），聊天不可用 |
| 端口被占 | 改 `config.json` 的 `server.port` 后重启 |
